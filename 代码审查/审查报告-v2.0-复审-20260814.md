## 三、新发现问题

### 🔴 H4（必须修复）：loading 页内联脚本被 CSP 拦截，启动过程依然"看不到"

**位置：** loading.html:94-118（内联 `<script>` 块）+ loading.html:5（CSP）

**问题：** CSP 为 `default-src 'self'; style-src 'unsafe-inline'; img-src 'self' file: data:`，**未声明 script-src**，内联脚本回退到 `default-src 'self'` —— **`'self'` 不允许内联脚本执行**。页面底部的内联 `<script>`（端口显示、onStage、onLog、setStage）**全部不会执行**。

**后果（严重）：**
- 阶段指示器不点亮、日志区不滚动、端口不显示 → **loading 页是纯静态页，"启动过程"依然看不见**
- 这解释了首版"看不到启动过程"的另一半根因（此前归因于窗口复用/黑屏，遗漏了脚本被拦）

**验证：** 启动应用，F12 控制台应出现 `Refused to execute inline script ... violates CSP`；loading 页阶段①~④全灰、日志空白。

**修复（推荐方案）：** 内联脚本提取为外部文件 + CSP 显式放行 file 源
```
1. 将 loading.html 底部 <script> 块移至 renderer/loading.js
2. 页面引用：<script src="loading.js"></script>
3. CSP 改为：
   default-src 'self' file: data:;
   style-src 'unsafe-inline';
   script-src 'self' file:;
   img-src 'self' file: data:
```
> 注意：`file:` 必须显式加入 script-src——file:// 协议下 `'self'` 对本地子资源的匹配不可靠（H1 同源坑），显式声明最稳妥。
> 备选（不推荐）：`script-src 'self' 'unsafe-inline'`（放行内联，页面无用户输入风险可接受，但不够严谨）。
