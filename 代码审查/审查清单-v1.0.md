# Windows软件（Electron）代码审查清单 v1.0

> 编制：26（技术总监）| 依据：Electron官方安全文档 + 社区实战最佳实践
> 用途：审查Windows桌面软件（Electron）代码的标准清单，按优先级排序

---

## 一、高危项（发现即打回，必须修复）

### 1. 渲染进程权限配置（最核心）
```js
// ❌ 高危致命配置（XSS可直接升级为系统级RCE）
webPreferences: {
  nodeIntegration: true,
  contextIsolation: false,
  enableRemoteModule: true   // 废弃高危模块
}

// ✅ 生产环境标准配置
webPreferences: {
  nodeIntegration: false,   // 关闭渲染进程Node权限
  contextIsolation: true,   // 开启上下文隔离
  sandbox: true,            // 开启渲染进程沙箱
  webSecurity: true,        // 开启Web安全
  preload: path.join(__dirname, 'preload.js')
}
```
**审查要点：** 远程页面/业务页面禁止开Node集成；contextIsolation必须true；sandbox生产必开。

### 2. IPC 通信安全
- ❌ 渲染进程传入的参数直接用于 `exec`/`spawn` → **命令注入RCE**
- ❌ IPC透传执行任意代码/路径
- ✅ 命令执行必须：指令白名单 + `execFile`参数分离（禁止字符串拼接）
- ✅ IPC接收参数必须：类型校验 + 路径白名单（禁止读取userData以外的敏感路径）
- ✅ 所有 `ipcMain` 监听器验证 `event.sender`（防伪造发送者）

### 3. 网络与协议
- ❌ 加载 `http://` 明文内容（必须HTTPS/WSS）
- ❌ `allowRunningInsecureContent: true`
- ❌ 对不可信内容调用 `shell.openExternal`（可被诱导打开恶意链接）
- ✅ 远程URL用 `webContents.session.setPermissionRequestHandler()` 管控权限

## 二、中危项（建议修复）

### 4. CSP 内容安全策略（防XSS核心防线）
```js
// 全局注入
session.webRequest.onHeadersReceived((details, callback) => {
  callback({ responseHeaders: {
    ...details.responseHeaders,
    'Content-Security-Policy': [
      "default-src 'self';",
      "script-src 'self';",            // 禁止外链/内联/eval
      "style-src 'self' 'unsafe-inline';",
      "img-src 'self' data:;",
      "connect-src 'self' https://*.your-domain.com;"
    ].join(' ')
  }})
})
// 页面头部加meta兜底
// <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self';">
```
**审查要点：** 必须配置CSP；`script-src`不允许`'unsafe-inline'`和`'unsafe-eval'`。

### 5. 窗口导航与新窗口管控
- ✅ `will-navigate` 拦截：只允许站内/白名单跳转
- ✅ `setWindowOpenHandler` 管控：新窗口统一处理，禁止 `window.open` 裸奔
- ✅ `<webview>` 不用 `allowpopups`，验证所有选项与参数

### 6. 敏感数据存储
- ❌ Token/密码/密钥明文存储（本地文件/配置）
- ✅ 对称加密存储（crypto-js 等），密钥不硬编码在代码里
- ✅ 日志脱敏：不打印Token、密码、完整路径

## 三、常规项（代码质量）

### 7. 版本与依赖
- ✅ 使用最新稳定版 Electron（旧版存在已知CVE）
- ✅ 依赖审计：`npm audit` 无高危漏洞；不用维护差/来历不明的库
- ✅ package.json 版本号语义化（x.y.z）

### 8. 更新机制（对应版本检查方案）
- ✅ 检查更新失败静默（超时3秒，不影响启动）
- ✅ 下载地址必须HTTPS；安装包校验hash
- ✅ 版本比较逐段数字，不字符串比较

### 9. 通用质量
- ✅ 主进程不阻塞（耗时操作放子进程/worker）
- ✅ 不直接暴露 `require`、`process`、`fs` 给渲染进程
- ✅ 自定义协议（app://）替代 file:// 加载本地资源
- ✅ 错误处理完整，无裸 catch、无未处理Promise rejection

## 四、审查流程

1. **先看主进程入口**（main.js）：BrowserWindow配置、CSP、IPC注册
2. **再看preload.js**：contextBridge暴露了哪些API（越少越好，白名单原则）
3. **检查IPC处理函数**：参数校验、路径白名单、命令白名单
4. **扫描危险API**：exec/spawn/eval/shell.openExternal/loadURL(远程)
5. **检查数据存储**：密码Token加密、日志脱敏
6. **依赖审计**：npm audit、Electron版本
7. **出审查报告**：高危/中危/常规三级 + 修复建议（只报告不改码）
