## 二、新需求1：菜单优化方案

### 现状问题（main.js:636-683）

| 问题 | 说明 |
|------|------|
| 功能重复 | "重新加载界面"和"开发者工具"在【文件】和【视图】两个菜单**各出现一次** |
| 归类不当 | 【文件】菜单放"开发者工具"（调试功能），不符合常规心智 |
| 缺关键入口 | 无"检查更新"、"打开数据目录"、官方链接入口 |
| 关于对话框 | 只显示版本信息，无"检查更新"按钮 |

### 优化方案（推荐）

```
📁 文件
 ├─ 重新加载界面        CmdOrCtrl+R
 ├─ 打开日志目录
 ├─ 打开数据目录        （%APPDATA%\DSH-Desktop）
 ├─ ────────
 └─ 退出

👁 视图
 ├─ 实际大小 / 放大 / 缩小
 ├─ ────────
 ├─ 全屏
 └─ 开发者工具          F12（调试功能集中于此，仅保留一处）

❓ 帮助
 ├─ 检查 DSH 更新        ★ 新功能（见第三节）
 ├─ ────────
 ├─ 关于 DSH-Desktop     （增加"检查更新"按钮 + 显示当前/最新DSH版本）
 ├─ ────────
 ├─ DeepSeek 官网        https://www.deepseek.com
 └─ DSH 项目主页         https://github.com/deepseek-ai/dsh（或官方文档）
```

**设计原则：**
1. **去重**：重新加载/开发者工具只保留一处（视图），文件菜单换成用户功能（日志/数据目录）
2. **按用途分组**：文件=应用操作；视图=显示；帮助=信息与支持
3. **"打开数据目录"** 对用户排查问题很有用（DSH装那里、日志也那附近）
4. 帮助菜单是放"检查更新"的合理位置（用户找"更新"通常在帮助/设置）

## 三、新需求2：DSH 官方版本检查功能设计

### 需求理解

检查 **npm 官方包 `@deepseek-ai/dsh`** 的最新版本（registry 上的 `dist-tags.latest`），与壳当前配置/已安装的 DSH 版本对比，提示用户是否有新版——**与套壳自身版本（app.getVersion()）无关**。

### 功能设计

**① 查询最新版本（核心函数，main.js 新增）：**
```js
const https = require('node:https');

/** 查询 npm registry 上 DSH 最新版本；失败/超时返回 null（静默） */
function fetchLatestDshVersion() {
  return new Promise((resolve) => {
    const cfg = readShellConfig();
    const pkgPath = cfg.dshPackage.replace('/', '%2f'); // scoped 包需编码 /
    const url = `${(cfg.registry || 'https://registry.npmmirror.com').replace(/\/$/, '')}/${pkgPath}`;
    const req = https.get(url, { timeout: 8000 }, (res) => {
      let body = '';
      res.on('data', (c) => (body += c));
      res.on('end', () => {
        try { resolve(JSON.parse(body)['dist-tags']?.latest ?? null); }
        catch { resolve(null); }
      });
    });
    req.on('error', () => resolve(null));
    req.on('timeout', () => { req.destroy(); resolve(null); });
  });
}
```

**② 版本比较（支持 rc 预发布号）：**
DSH 版本形如 `0.1.0-rc.6`，需扩展比较函数（当前 compareVersion 只处理 x.y.z）：
```js
/** 语义化比较，支持 -rc.x 预发布：正式版 > 预发布版；返回 1/0/-1 */
function compareSemver(a, b) {
  const pa = String(a).split('-'), pb = String(b).split('-');
  const va = pa[0].split('.').map(Number), vb = pb[0].split('.').map(Number);
  for (let i = 0; i < 3; i++) {
    const x = va[i] || 0, y = vb[i] || 0;
    if (x !== y) return x > y ? 1 : -1;
  }
  const ra = pa[1] ? 0 : 1, rb = pb[1] ? 0 : 1; // 无预发布号视为正式版
  if (ra !== rb) return ra > rb ? 1 : -1;
  return 0;
}
```

**③ 检查流程（两种触发方式）：**

*方式A：启动时静默检查（推荐，不打扰）*
```
启动完成后（服务就绪后）异步调用 fetchLatestDshVersion()
→ 有新版：仅记日志 + 帮助菜单"检查 DSH 更新"项加 "（有新版本）" 后缀提示
→ 无新版/失败：静默
```

*方式B：手动检查（菜单点击 / 关于对话框按钮）*
```
点击"检查 DSH 更新" → 弹窗：
  [检查中…] → 结果：
  当前版本：0.1.0-rc.6（配置）
  最新版本：0.1.0-rc.7
  [有新版] → 提示"修改 app/config.json 的 dshVersion 为 0.1.0-rc.7，
             重启应用后自动升级"（当前架构天然支持：启动时版本不符会重新 install）
  [无新版] → "已是最新版本"
  [失败]  → "无法连接 npm 源，请检查网络"
```

**④ 升级体验设计（关键）：**
当前架构下升级 = 改 config.json 的 `dshVersion` + 重启应用（ensureDshRuntime 检测版本不符自动重装）。所以"检查更新"功能**不需要做下载/安装**，只需：
- 查到新版 → 弹窗显示新旧版本 + 更新日志（可拉取 npm 包信息里的 description/readme 摘要）
- 提供按钮【立即升级】：**自动改写 config.json 的 dshVersion** → 提示重启 → 重启后自动安装新版
- 改写前备份 config.json（一行代码，防手滑）

### 边界与注意

| 项 | 说明 |
|----|------|
| 静默失败 | 断网/源不可达时无任何打扰，仅日志 |
| registry 一致性 | 查询用 config.json 的 registry（npmmirror），与安装源一致 |
| pre-release | 用 compareSemver 处理 -rc.x；若只想提示正式版，可过滤 dist-tags.latest 为 rc 的情况（可选）|
| 自动升级按钮 | 改 config.json 前先备份；重启提示用 dialog + app.relaunch() |
| 防抖 | 手动检查加 10 秒冷却，防连点 |
