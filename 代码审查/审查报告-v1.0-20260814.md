## 一、项目概况

DSH-Desktop 是 DeepSeek Harness Web GUI 的 Electron 纯套壳：
- 壳自带 npm 运行环境，启动时按 config.json 配置版本 `npm install` 拉取 `@deepseek-ai/dsh` 到用户数据目录
- 以子进程启动 `dsh web`（127.0.0.1:3080，占用自动顺延），就绪后在同一窗口中加载 GUI
- 打包：electron-builder + NSIS（per-user，免管理员），**asar 关闭**
- 依赖极简（运行时仅 npm 一个依赖），攻击面小

**总体评价：** 架构清晰、安全基线良好（沙箱/隔离/白名单齐全），主要问题集中在**启动流程的窗口管理与体验**（正是老大反馈的两个已知问题），另有 1 个进程残留隐患。

## 二、已知问题专项分析（启动界面）

### 问题1：logo 图片没有正常显示 🔴

**根因（高概率）：CSP 拦截。**

`app/renderer/loading.html` 第 5 行：
```html
<meta http-equiv="Content-Security-Policy" content="default-src 'self'; style-src 'unsafe-inline'" />
```
第 58 行：
```html
<img class="logo" src="../assets/icon.png" alt="DSH-Desktop" />
```

**证据链：**
1. `app/assets/icon.png` 存在（73KB）✅
2. 相对路径 `renderer/../assets/icon.png` 正确解析到 `app/assets/icon.png` ✅
3. CSP 未显式声明 `img-src`，仅靠 `default-src 'self'` ⚠️
4. 页面通过 `win.loadFile()` 以 **file:// 协议**加载 —— 在 file:// 页面中，`'self'` 指向 opaque origin，**不能稳定匹配 file:// 子资源**（Chromium 已知行为，Electron 常见坑），图片被 CSP 拦截，控制台会报 `Refused to load the image ... because it violates CSP`

**验证方法：** 启动应用按 F12 打开开发者工具，Console 若出现上述报错即坐实。

**修复建议（二选一）：**
```html
<!-- 方案A：CSP 显式放行 file: 图片 -->
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; style-src 'unsafe-inline'; img-src 'self' file: data:" />
```
```html
<!-- 方案B（推荐）：logo 直接内联 base64，彻底免疫 CSP 与路径问题 -->
<img class="logo" src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAAB..." />
```
> 方案B 附带好处：打包后不依赖资源文件路径，减小安装包体积，任何环境都能显示。

### 问题2：看不到启动过程 🔴

**根因：三个叠加因素。**

**因素A（代码级 bug）：loading 窗口与主窗口复用，主窗口设计尺寸从未生效。**
- `createLoadingWindow()` 创建 1280×820 窗口并赋给 `mainWindow`
- 服务就绪后第 592 行 `mainWindow.loadURL(webUrl())` —— **复用同一窗口**
- `createMainWindow()`（1440×900）只在 `mainWindow === null` 的 else 分支执行，**正常启动流程永远走不到**
- 结果：主窗口实际尺寸 = 1280×820，与设计不符

**因素B：GUI 加载期间窗口空白。**
- `loadURL(DSH GUI)` 后到 `did-finish-load` 之间，窗口只有深色背景（#0f1115），无过渡动画、无加载提示
- DSH Web GUI 是较重的前端应用，首次加载可能需要数秒——用户看到的就是"黑屏无反应"

**因素C：首次启动 npm install 无进度感。**
- 首次运行下载 DSH 运行时可能耗时数分钟，loading 页只有 spinner + 技术日志（npm 原始输出）
- 无进度条/百分比/阶段提示，普通用户无法判断"正在下载"还是"卡死了"

**修复建议（分层）：**

1. **拆窗口或补尺寸（必须）**：服务就绪后关闭 loading 窗口、`createMainWindow()` 新建主窗口；或复用窗口时 `win.setSize(1440, 900)` 修正
2. **阶段化启动进度（推荐）**：loading 页改为步骤指示器，主进程通过 IPC 推送阶段：
   ```
   ① 检查 DSH 运行时 → ② 下载/安装（可显示百分比）→ ③ 启动服务 → ④ 就绪
   ```
3. **npm 进度获取**：`npm install --json` 解析 progress 事件，或轮询 `dshenv` 目录体积/文件数估算进度
4. **GUI 加载过渡**：主窗口先显示"正在加载界面…"覆盖层，`did-finish-load` 后淡出

### 🔴 高危（必须修复）

| # | 位置 | 问题 | 建议 |
|---|------|------|------|
| H1 | loading.html:5 | CSP `default-src 'self'` 在 file:// 下拦截本地 logo（已知问题1根因） | CSP 加 `img-src 'self' file: data:` 或 logo 内联 base64 |

### ✅ 做得好的（保持）

1. **安全三件套齐全**：两个窗口均 `nodeIntegration: false` + `contextIsolation: true` + `sandbox: true`
2. **preload 最小暴露**：仅 3 个只读 API（getVersion/getPort/onLog），无高危通道
3. **外链管控**：`setWindowOpenHandler` 一律 deny + `shell.openExternal`（HTTPS 才放行）
4. **导航白名单**：`will-navigate` 仅允许本地服务地址
5. **单实例锁**：`requestSingleInstanceLock` 防多开，二次启动聚焦已有窗口
6. **遥测默认关闭**：`DSH_TELEMETRY_DISABLED=1`
7. **错误可诊断**：启动失败弹窗带日志路径；日志环形缓冲 + 落盘
8. **依赖极简**：运行时仅 npm 一个依赖；Electron ^43.4.0 为当前主版本
9. **安装器配置合理**：per-user（免管理员）、向导式、多语言、asar 关闭（纯套壳无敏感逻辑，可接受）

## 四、安全面说明（供知悉）

- `--expose-internals`（main.js:360）：打包模式下 Electron-as-Node 运行 DSH 需 Node 内部模块，DSH 为官方 npm 包（受信任源），风险可控；建议在文档中注明此信任边界
- `asar: false`：代码明文分发。本壳无密钥/敏感逻辑，可接受；若未来壳内引入敏感逻辑需重新评估
- `config.json` 的 registry 可被用户修改：信任本地用户，无风险
